Project Overview

The Resume Analyzer is a Spring Boot REST API that automates resume screening. Submit a resume file in any common format and a job ID, and receive a compatibility percentage score plus lists of matching and missing skills. Built to give candidates and recruiters concrete, actionable data instead of gut-feel decisions.

The core insight was that most resume screening is just pattern matching — does this document contain the keywords required by this job? Combining Apache Tika's document parsing with a curated regex skill-extraction engine and MySQL-backed job requirement storage turns that match into a structured, queryable system.

Processing Pipeline

Resume → Match Score
1
File Upload — Client POSTs a multipart resume file (PDF, DOCX, TXT, RTF) + job ID to the API.
2
Apache Tika Parsing — Tika auto-detects format and extracts raw text, normalising encoding and whitespace.
3
Skill Extraction — 200+ regex patterns run across the text to identify technical skills (languages, frameworks, tools).
4
Job Requirement Lookup — Required skills for the target job are fetched from MySQL via Spring JDBC + JdbcTemplate.
5
Match Calculation — Intersection of resume skills and job skills computes a compatibility %. Missing skills returned as actionable gaps.

API Endpoints

POST/api/resume/analyzeUpload resume + job ID → match score
GET/api/jobsList all job requirements
POST/api/jobsAdd new job + required skills
GET/api/skillsBrowse extractable skill catalog

Challenges & Solutions

⚠ Challenge
The same skill appears in many forms: "Node.js", "NodeJS", "node js". Simple string matching missed large numbers of valid entries.
✓ Solution
Built a normalisation layer mapping all known variants to canonical skill names before comparison. Patterns use case-insensitive flags and word-boundary anchors to catch variations without false positives.
⚠ Challenge
Scanned or image-based PDFs returned empty text from Tika, silently returning 0% match scores — a common real-world scenario.
✓ Solution
Added a pre-processing check: if extracted text length falls below a threshold, the API returns a clear 422 error ("Unable to extract text — may be a scanned image PDF") rather than a silent wrong score.
