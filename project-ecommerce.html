Project Overview

A production-grade e-commerce backend built on a microservices architecture, where each business domain — users, products, orders, inventory, payments, and notifications — is isolated into its own independently deployable service. All traffic routes through a Spring Cloud API Gateway, with Eureka handling service discovery.

The goal was to go beyond tutorials and build something that reflects genuine enterprise patterns: fault tolerance, distributed security, database isolation, and containerised deployment. Every design decision was intentional and production-minded.

Key Features

  • Eureka Service Discovery + API Gateway
    All 7 services register with Eureka at startup. Spring Cloud Gateway handles intelligent routing, load balancing, and rate limiting — the single entry point for all client traffic.
  • Stateless JWT Authentication
    Spring Security with BCrypt issues JWTs validated at the gateway level. No session state — truly stateless and horizontally scalable.
  • Resilience4j Circuit Breakers
    OpenFeign clients between services are wrapped with circuit breakers and retry policies. If the Inventory Service goes down, the Order Service degrades gracefully rather than cascading failures.
  • Database-per-Service Isolation
    Each microservice owns its own MySQL schema — zero cross-service database coupling. Pessimistic locking in Inventory Service handles concurrent stock updates safely.
  • Multi-Stage Docker Compose Orchestration
    Multi-stage Dockerfiles minimise image size. A single docker compose up spins up all 7 services with correct networking and health checks.

Challenges & Solutions

⚠ Challenge
Concurrent stock updates from multiple Order Service instances caused race conditions — two orders could both see stock = 1 and both succeed, resulting in overselling.
✓ Solution
Implemented pessimistic locking (SELECT FOR UPDATE) in the Inventory Service so only one transaction can read-and-decrement stock at a time, preventing overselling under concurrent load.
⚠ Challenge
If one service was down, all dependent services would hang indefinitely, causing cascading timeouts across the system.
✓ Solution
Configured Resilience4j circuit breakers with fallback methods and exponential retry backoff. Services now fail fast and return graceful error responses when dependencies are unavailable.
